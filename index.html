Things I've built 01

Practice website scanner

Private · Velari

The scanner from the top of the page. It opens a practice's site in a real browser and checks what a patient would run into, plus what they'd never see. That means ad trackers on appointment pages, missing or broken email security records, bad redirects, expired certificates, dead links, accessibility errors, and whether the privacy notice is posted and current.

The first run on 11 St. Louis practices found 53 issues. Each one gets checked again by hand before it goes anywhere.

Python · Playwright · DNS and TLS checks · axe-core

Access review

Private · on request

Pulls accounts from Google Workspace, Entra ID and AWS IAM into one place. Each of those systems only shows its own accounts. So when someone leaves, it's easy to remove their email and miss their AWS access. You only catch that when you see all three side by side.

It flags admins without MFA, old accounts that still have admin rights, third-party app grants and access keys. Then it turns them into a fix list with an owner on every item.

Python · OAuth with PKCE · Entra ID · Google Workspace · AWS IAM

Small Practice Security Kit

Public

A practice answers a set of intake questions and gets back a plan. It shows where patient data lives, which vendors need a BAA, what proof is missing, and what to fix in the next 30, 60 and 90 days. It's written for the office manager, not for an IT person.

Python · 30 controls · 127 tests · synthetic data

HealthAI Audit

Public · live demo

Practices are adding AI scribes and chatbots faster than anyone is reviewing them. This tool takes an inventory of the AI tools a practice uses and checks each one for a BAA, how it handles patient data, and what an agent is allowed to do. The result is a dashboard the owner can read.

Python · CLI · single-file HTML dashboard

Guardrails for AI agents

Public

Rules that run before an AI agent is allowed to act on patient data. The rules check who's asking, why, and whether the vendor has a BAA. Then they allow the action, redact it or block it, and log the decision. Plain rules decide, so nothing depends on a model behaving.

Python · 6 roles · 16 allow/block test cases · no model calls

Labs 02

Practice Trust Lab

Public

A fake clinic in Docker with an Active Directory domain, joined machines, file shares and a mock EHR. I planted a compromised npm package and copied patient records onto desktops to see if my own reporting would catch it.

Service Desk Lab

Public

osTicket in front of a Samba AD domain on my own server. I worked tickets against it for new hires, lockouts, access changes and offboarding, and wrote a runbook for each one.

SQL injection write-up

Public

OWASP Juice Shop in Docker, picked apart for real vulnerabilities. I tested broken access control, IDOR and SQL injection, then wrote the one that mattered up the way a real coordinated-disclosure report is written: severity scored with a CVSS vector, reproduced twice from a clean container, and backed with screenshots of the actual exploit.

curl · Docker · JWT decoding · CVSS 3.1
