Practice Trust Lab

Public · lab + evidence packet

A synthetic small clinic that stands itself up in Docker: a Samba Active Directory domain with AGDLP group nesting and least-privilege share ACLs, domain-joined endpoints, clinical file shares, a mock EHR, and simulated AI-scribe egress. A read-only Python pass collects identity, share, authentication, endpoint, and supply-chain signals and renders a dated, no-PHI review packet: decision brief, evidence schedule with stable references, reviewer lanes, and a change monitor.

The packet runs on proof, not narrative: clinical exports on shares are matched by SHA-256 to copies cached on endpoint desktops, and the supply-chain scan catches a planted shadow-IT app pinned to a known-compromised npm release. Negative tests are part of the demo: clinical users can read ClinicalShare, IT is denied there but allowed ITShare, and temporary-password users cannot authenticate.

this is the project that turned HIPAA reading into something I can evidence. Standing up the environment, breaking it on purpose, and shipping a packet that cites its own proof is the difference between describing a control and demonstrating it.

Samba AD DC · Docker Compose · Python · hash-matched file inventory · drift detection · package-exposure scan · Linux

Cloud/IAM Access Review Analyzer

Private · on request

A local-first analyzer that normalizes Google Workspace, Microsoft Entra ID, and AWS IAM exports into deterministic access-review findings: admins without confirmed MFA, stale privileged accounts, OAuth and enterprise app grants, access keys, and root-account settings. It is the companion module to the public Small Practice Security Kit.

Generates remediation queues, owner and MSP action plans, CSV/JSON exports, and a static local dashboard, all mapped to NIST and HIPAA control language. A local wizard handles browser OAuth (PKCE), capability probes, and packet build and validation without sending practice data to another SaaS.

access review is where identity work meets client work. Deciding what a practice owner should ask the MSP to fix first is a different problem from listing findings, and that is the part I kept working at.

Python · OAuth 2.0 + PKCE · Entra ID / Google Workspace / AWS IAM · local dashboard · synthetic sample data

Service Desk Lab

Public · home lab

A one-person Tier 1 lab: an osTicket queue and a Samba Active Directory domain controller, both in Docker on my own server and reachable only over my Tailscale network. OUs, security groups, synthetic users, and a lockout policy, administered headless with samba-tool and LDAP over SSH the way real domain controllers are.

Six scenarios worked end to end as real tickets: new hire provisioning, password reset, lockout investigation, access change, offboarding, and remote administration, each closed with resolution notes and written up as a runbook.

certs teach concepts, service desk work is tasks. Doing the account lifecycle by hand against a real directory, and writing it down where the next tech could follow it, is what made the identity and ITIL material stick.

osTicket 1.18.4 · Samba AD DC · LDAP / Kerberos · Docker · Tailscale · Linux

Small Practice Security Kit

Public · tested

A local-first tool that turns a small practice's intake answers into a HIPAA readiness packet: where ePHI actually lives, which vendors need BAAs, which evidence is missing or stale, and a 30/60/90-day action list. Runs on a synthetic clinic profile, never real patient data.

30 controls mapped across five families (12 technical, 6 administrative, 6 vendor and BAA, 4 operational, 2 physical), with a 127-test suite. The output is written so a non-technical owner can act on it.

most of the work here was domain, not code. Reading the HHS Security Rule, 405(d), and CISA's baseline goals closely enough to decide what a small practice actually has to answer is the part I can stand behind.

Access Guardrails for AI Agents

Public

Deterministic RBAC, purpose-of-use, BAA/vendor-status, and PHI-pattern checks that run before an AI agent is allowed to act, with block, redact, and proceed paths and an audit log.

Six clinical roles and 16 ALLOW/BLOCK eval cases, all decided by rules rather than by asking a model. Synthetic data only.

this one is closest to how I think work is heading. Keeping AI useful in healthcare means putting hard, checkable rules in front of it instead of trusting it to behave, and building this is how I started to see where those rules have to live.

Pace

Private · in development

An Apple Watch movement-coaching prototype. It reads wrist motion during dumbbell curls, detects the lift, top, and lower phases of each rep, and coaches lowering tempo with haptics. All detection runs on the Watch: no account, no network, and no sensor data ever leaves the device.

Swift and watchOS from scratch, and how much care real signal processing takes. I wrote the rep detector as a tested state machine, replay recorded motion as regression fixtures, and kept the docs honest about what the sensors can and can't prove.

Swift · SwiftUI · watchOS · HealthKit · Core Motion · on-device, no network · CI + golden-fixture tests
