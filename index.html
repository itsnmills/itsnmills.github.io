Small Practice Security Kit

Public · tested

A local-first tool that turns a small practice's intake answers into a HIPAA readiness packet: where ePHI actually lives, which vendors need BAAs, and a 30/60/90-day action list. Runs on a synthetic clinic profile, never real patient data.

most of the work here was domain, not code. Reading the HHS Security Rule, 405(d), and CISA's baseline goals closely enough to decide what a small practice actually has to answer is the part I can stand behind.

PHI Guardrails for AI Agents

Public

Deterministic RBAC, purpose-of-use, BAA, and PHI-pattern checks that run before an AI agent is allowed to act, with block, redact, and proceed paths and an audit log.

this one is closest to how I think work is heading. Keeping AI useful in healthcare means putting hard, checkable rules in front of it instead of trusting it to behave, and building this is how I started to see where those rules have to live.

Also building 03 · Pace

Not everything I build is security work. Pace is a personal project that connects my exercise-science background to the engineering side I'm growing into: an Apple Watch and iPhone app that coaches lifting tempo from wrist motion, entirely on-device.

Pace

Private · in development

An Apple Watch movement-coaching prototype. It reads wrist motion during dumbbell curls, detects the lift, top, and lower phases of each rep, and coaches lowering tempo with haptics. All detection runs on the Watch: no account, no network, and no sensor data ever leaves the device.

Swift and watchOS from scratch, and how much care real signal processing takes. I wrote the rep detector as a tested state machine, replay recorded motion as regression fixtures, and kept the docs honest about what the sensors can and can't prove.

Swift · SwiftUI · watchOS · HealthKit · Core Motion · on-device, no network · CI + golden-fixture tests
